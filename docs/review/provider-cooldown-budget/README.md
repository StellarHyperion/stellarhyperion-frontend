# Provider cooldown and approved fee budgets

The fee endpoints share the existing bounded process admission budget. Each provider also has one process cooldown, shared across destinations, so repeated requests during a provider delay do not reach the upstream service. Both endpoints return `RATE_LIMITED`, a bounded integer `retryAfter` and `Retry-After`; missing metadata uses five seconds and zero still blocks for one second. Positive integer seconds and HTTP dates are accepted, with a maximum of 60 seconds. Oversized or invalid successful provider responses remain unavailable. No failed quote supplies an executable fee.

The client shares each provider deadline across changing composer inputs. It stops the existing immediate retry for rate-limited responses. Amount, source asset and recipient remain in place; the receive amount shows Unavailable during a quote failure. The explicit retry button counts down and stays disabled until the provider deadline passes. Reaching the deadline does not automatically fetch or sign.

Fee details keep protocol USDC fees, provider estimates, the exact approved budget and integer rounding headroom separate. Axelar approvals use seven-decimal XLM; Circle approvals use seven-decimal USDC and preserve destination six-decimal payout precision. The headroom row is the actual approved amount minus its estimate, using the same integer units as the request. Refunds depend on provider behavior.

The browser fixture mounts production Bridge and Providers. RPC, Horizon, EVM, provider and Freighter transports are mocked with an unfunded synthetic signer. For both ITS and CCTP it blocks pricing on upstream 429, verifies one provider request despite changing recipient input, preserves inputs, waits for explicit retry, and checks exact headroom and refund disclosure. It then exercises quote worsening, fresh review, improvement display with immutable signed budgets, valid signature verification and durable recovery after lost acknowledgement. No external transaction or payment is broadcast. Desktop and mobile captures record cooldown and fee details; mobile overflow is checked.

The build uses standard production Turbopack minification with browser source maps. Actual emitted JavaScript maps retain module membership even when package names disappear from minified text. Installed module maps resolve upstream TypeScript and webpack source URLs back to exact native client modules; native sync/async importer edges then identify per-route responsibility. First-load manifest filenames and actual file sizes verify eager loading and complete chunk budgets. Missing, stale or unjoined evidence rejects the check. Wallet adapter and transaction budgets remain 450,000 and 1,200,000 uncompressed JavaScript bytes, deduplicated across application routes. The report is `.next/diagnostics/bundle-attribution.json`.

Full validation, current source fingerprints and final emitted build totals are recorded alongside this evidence after the final source is frozen.
