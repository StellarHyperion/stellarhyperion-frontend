# Provider observations and public payment proof

A fee response now binds the provider, currency, decimal precision and Stellar Testnet destination/route identity to strict UTC observation and expiry timestamps. A response can qualify for current review only when its observation differs from the client by at most five seconds and its positive validity window is at most 30 seconds. The client reserves the full five-second allowance from the displayed expiry. Clock rollback or expiry makes the observation stale; a fresh fee read remains required before signing. Failed pricing remains unavailable and preserves amount/recipient inputs.

The transfer proof drawer reads the implemented numeric-id `GET /v1/transfers/:id/evidence` contract on explicit expansion. It projects only bounded public command, transaction, block, token and payment fields. Arbitrary provider payloads and credential-bearing URLs are omitted. Candidate evidence stays unverified until all five stored checks and the exact recorded destination transaction, block, recipient, token and amount agree. Command/receipt details for providers without this backend contract remain explicitly unavailable. Full identifiers can be selected and copied; keyboard expansion and 390px layouts were verified.

The independent envelope tests inspect the actual production conversion, bridge and batch settlement builders after XDR assembly. Literal review expectations cover trustline issuer, payment maximum/receive amount, recipient, router, token, gas budget and ordered claim identifiers. Real deterministic local signatures are accepted only for the original Testnet envelope; altered operation, fee and network signatures are refused. These tests do not call the production intent comparison helpers to create their oracle.
