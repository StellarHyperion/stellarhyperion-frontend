# Typed transaction messages and live fee availability

Submission, signed-source recovery and claim-settlement phases use typed English fallback messages. A partial translation catalog can replace each message with typed variable arguments. Missing, empty or failed translations retain the complete English guidance for the same state. Amount labels receive an exact decimal string and its unit label; transaction parsing continues to use the original input and immutable asset/intent data. Translation cannot change integer parsing or signing budgets. Both source and destination amounts retain their own decimal precision.

Both implemented fee endpoints expose explicit public HEAD capability markers without a provider request or a fee estimate. Discovery is bounded by one shared five-second deadline, supports cancellation and admits the two rails independently. Missing endpoints, generic HTML fallback responses, failed responses and unrecognized route markers cannot enable priced review or signing. Manual retry admits one current two-endpoint read even after rapid repeated activation. An available route still requires a fresh validated fee, simulation and explicit wallet approval. Unsupported pricing retains entered values, and its stopped read does not show a permanent loading state.

The source-status recovery path and configured read-only history remain usable when pricing endpoints are missing. A confirmed conversion retains its original signed hash and existing USDC; it cannot approve a fresh bridge while the selected fee endpoint is unavailable. Recent local references retain their account scope and distinguish locally observed source confirmation from indexed destination delivery.
